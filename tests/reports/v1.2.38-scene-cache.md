# v1.2.38：多采样率场景缓存分层

2026-10-21，针对固定 backlog 第 19 项补测并实施。此前只有缓存预算、LRU 与会话释放，未证明是否需要拆分几何与采样数据；本轮先用相同场景的多采样率实际测量，再按观测结果拆分。

## 输入与方法

自制外置缓冲 glTF：32,761 顶点、64,800 三角形、4 个 morph、2 秒骨骼位移动画。同一个 QC 以 15、24、30、60、120 FPS 载入同一源场景；分别测试原生和 `$NoFastGltf` 两个后端，以及 `$SceneCacheMiB 0` / `256`。每组 1 次预热、5 次测量；相邻轮次颠倒组顺序。

输入 `scene.bin` SHA-256：`96cc4d824767a4ad337ab4b459feaef4a676f59ca8e60aa8c8e025fb9b6c7c99`。
输入 `scene.gltf` SHA-256：`658dd939a8cfd6d40d27e300d57d8990584e03706e2f0a2db9348c9ac7afd99d`。

两个程序均为同一 Windows 主机的 MSVC Release 开发构建。旧程序 SHA-256：`4ebda19076e4180c12c0d02d98ad13ceb8c51106dd317cfe5be22123241d720e`；分层后程序 SHA-256：`f4560bd9926b3e7a2d99bf40b063df89ba0bdd91e0d71c03b02d5f5dfd8e5e89`。首次进程并未清空系统磁盘缓存，不能称为冷盘测试。

## 观测与决策

旧实现启用缓存时，两后端均产生 5 个采样率不同的完整场景（5 misses、1 hit、零淘汰），每个场景重复保留相同几何。关闭时为 6 次完整导入。几何占用明显，因此实施共享不可变几何、独立采样动画的最小分层。

| 后端，缓存 256 MiB | 原估算驻留峰值 B | 分层后估算驻留峰值 B | 降幅 |
| --- | ---: | ---: | ---: |
| native | 22,952,865 | 4,647,853 | 79.75% |
| assimp | 23,021,580 | 4,665,740 | 79.73% |

分层后两后端均记录 **1 次几何导入、4 次几何复用、5 个采样条目**。几何按唯一共享对象计入预算；最后一个引用被淘汰时才从缓存统计移除。QC 结束后实际缓存容器清空，估算驻留归零。

| 分层后后端/缓存 | 导入耗时中位 ms | 全程中位 ms | 进程 working-set 峰值中位 MiB |
| --- | ---: | ---: | ---: |
| native / 0 MiB | 30.042 | 1053.29 | 78.14 |
| native / 256 MiB | 13.174 | 1011.72 | 78.14 |
| assimp / 0 MiB | 42.822 | 1046.28 | 79.10 |
| assimp / 256 MiB | 15.795 | 1047.27 | 79.75 |

缓存对象的估算占用显著减少，但进程峰值 working set 基本未下降，编译后的 Source 数据与后续阶段仍占用内存。导入阶段可观察到开关差异，其他阶段占总体耗时的大部分。两轮测试间系统存在并行负载变化，旧/新全程耗时不能作为整体提速证据。估算 aiScene 字节也不包含全部分配器与瞬时导入开销。

## 实现边界与回归

- 仅对不含 `EXT_mesh_gpu_instancing` 的 glTF、GLB、VRM 拆分；原生与 Assimp 几何仍按各自后端隔离。GPU 实例可能生成额外动画骨架，C4D 有转换生命周期，其余导入器采样语义不同，均保留原整场景路径。
- 原采样率和 bake 开关键继续隔离动画；完整源依赖戳在共享前复查。采样对象拥有自己的 aiScene 动画数组，几何拥有自己的层级/mesh，未混用拥有所有权的裸数组。
- 动画单独重采样时保留原生/Assimp 各自的未命名节点规则；同样解码 meshopt 动画访问器，避免读取与权威压缩数据不同的 fallback。
- 新增跨采样率开关产物等价、未命名节点、共享预算/缩容、压缩动画权威数据回归。连同现有 STEP/CUBIC、bake、skin、GPU 实例、VRM、Draco/meshopt 等定向检查，共 **28 项通过**。首次自制选择器的运行因未提供测试辅助代码要求的 `__main__.COMPILER` 而报 Python harness 错误；按正式 `compatibility.py` CLI 重新执行全部 28 项后零失败、零错误、零跳过。
- 所有原/新版本、缓存开/关、各次测量的完整 MDL/VVD/VTX 文件 SHA-256 逐一相同；输入 fixture 散列也相同。此结果覆盖该自制场景与回归样本，不代表任意场景的连续动画/游戏误差认证。

此前 [Windows 全套 737 项](v1.2.38-final-source-regressions.md) 对应分层前程序。随后对分层后程序重跑完整 compatibility：**445 项、81.092 秒，零失败、零错误、零跳过**；其余未改子工具/helper 的 295 项沿用之前结果。28 项定向检查属于完整 compatibility 的子集，不能重复相加。
