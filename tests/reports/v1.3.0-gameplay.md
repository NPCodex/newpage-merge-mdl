# v1.3.0 L4D2 实际玩家与热重载验收

2026-10-25，在本机 L4D2 `2.2.4.3`、网络版本 `2.1.0.0`、引擎 build `10097`
的离线监听服务器 `c8m1_apartment` 上完成有限范围验收。完整 Rochelle 网格使用普通
`swap.qci` 填充 Zoey 的序列索引；实际操作对象是本地幸存者玩家，包含移动、持枪、射击、
弹匣重装及 L4N 引擎模型缓存刷新。这里不是独立 `prop_dynamic` 或仅播放指定序列的结果。

- 原始输入为此前已修复浮点权重读取的 Rochelle 真实模型反编译目录；本次复制后改为独立

- 使用普通 `swap.qci`，不是 `swap_Light.qci`。前两个本地序列为 `TeenAngst` 和 `ragdoll`；
  945 个后续槽中 821 个采用 donor、124 个保留目标 fallback；只有 QCI 中两段战役动画使用

## 实际玩家动作

地图内先 `sb_takecontrol Zoey`，确认原模型为 `models/survivors/survivor_teenangst.mdl`，
该 L4D1 roster 的 `m_survivorCharacter=1`。随后对同一真实玩家替换上述编译模型。
本地 `sv_lan 1`、`-insecure`、`director_stop`、`god 1`、`sb_stop 1` 用于有限、可重复的验收。
采样原生玩家速度/位置、序列、武器、弹匣、重装状态和四个挂点；动作由实际输入命令触发。

| 动作 | 引擎读回证据 |
| --- | --- |
| 持 rifle 站立 | `Idle_Standing_Rifle`，弹匣 50，持有者是同一玩家 |
| 步行/跑步 | 实际水平速度最高分别为 85.0012 / 220.001 units/s，位置移动；出现 `Walk_Rifle` / `Run_Rifle` |
| 蹲伏/起身 | `m_fFlags` 的 duck 状态 false/true，`Idle_Crouching_Rifle`；第三人称画面确认蹲伏姿态 |
| Rifle 射击/重装 | 弹匣 50→23→50，`m_bInReload` 0→1→0 |
| Pistol 射击/重装 | 双持弹匣 30→29→30，`m_bInReload` 0→1→0 |
| 抬枪/压枪 | 俯仰 -35° / +35°，保留实际持枪模型，眼/weapon_bone 挂点坐标变化 |

最终采用的采样块保存 204 条不同 tick 的完整样本：玩家始终使用测试模型，武器持有者均正确，
`weapon_bone`、`lfoot`、`rfoot`、`eyes` 及位置/速度均为有限值，采样异常 0。
首次脚本的 `.1` 数值写法解析失败已改为 `0.1`；初期直接读取 bool duck 字段的采样被排除，
最终使用 `m_fFlags & 2`。初始化、被排除的尝试与最终记录都保留，未覆盖失败证据。
步行路径经过屋顶高低差并触发 `Jump_Rifle_02`，随后跑步撞到边界停止；没有将整个采样期描述为匀速移动。

## 实际 L4N 模型重载

使用同一个模型路径、同一个玩家实体，在 QC 加入唯一的 `npmdl_reload_probe` 挂点，
重新编译并同步五个模型文件，然后由编译器 `-reloadpid 13644` 发出通知。
游戏读回挂点索引从 `0`（不存在）变为 `30`，挂点位置为有限向量。

反向对照更严格：恢复原 QC、重新编译并把原模型放回磁盘，通知前同一玩家仍读到挂点 `30`；
再次经编译器通知后，同一玩家读回 `0`。期间没有 `SetModel`、重启地图或重建玩家。
因此该安装环境中验证了实际模型缓存刷新，而不只是 Windows 消息投递返回成功。
通知后 rifle 仍存在、弹匣 50、持有者正确，第三人称仍显示完整测试模型。

这是一个已安装 L4N 环境、一个明确 PID/窗口的往返重载验收；多窗口、超时、无候选、
接收端返回零等自动化协议覆盖另见重载测试，不由本次游戏会话推断。
