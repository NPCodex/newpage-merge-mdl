# v1.3.0 Windows 重载目标选择验证

验证日期：2026-10-25。本地 Windows/MSVC Release 编译器 SHA256：`2a6d31ab139415d0c28f6af18324e317ae340b9b45a5aa984269656b1cc4daf8`。本记录验证发送协议及目标选择，不声称真实游戏已完成重载。

`-reloadhlmv` 在成功写出后枚举当前桌面的 `Valve001` 顶层窗口，只向唯一候选发送 L4N 兼容消息。新增 `-reloadpid <十进制 PID>` 隐含启用重载，将候选限定到指定进程；目标不存在时不会退回其他进程，同一 PID 有多个候选时也不猜测。编译日志区分无目标、歧义、发送超时/失败和已投递，并明确已投递不等于游戏重载成功。失败或跳过游戏请求后仍尝试原有 HLMV 通知。

```text
NewPageMergeMDL model.qc -game <mod-directory> -reloadpid <game-pid>
python tests/neko24_reload.py <compiler> --require-all -v
```

14 项隔离回归全部通过，0 跳过：唯一候选兼容协议、两个不同进程的歧义、分别选择新/旧进程、同一 PID 两个窗口、错误 PID 不回退、无窗口、非法/缺失 PID、接收端返回 0、1 秒超时、`-verify`、编译失败和不启用重载均不误发；HLMV 精确模型标题及成功路径仍保持原行为。

接收器和编译器运行在从未显示的私有 Windows 桌面。第二接收器使用独立 Python 进程，协议测试只创建自己的隐藏窗口；测试没有向真实游戏发送重载消息。空桌面枚举返回零且 `GetLastError()==ERROR_SUCCESS` 的情况作为无候选处理，这一点由独立空桌面测试覆盖。

`Valve001` 窗口类不能证明安装了 L4N；PID 选择只确定接收进程。`WM_COPYDATA` 投递成功及接收端返回值都不能替代游戏内资源、材质或动画验收。真实应用结果应在游戏验收报告中单独记录。
