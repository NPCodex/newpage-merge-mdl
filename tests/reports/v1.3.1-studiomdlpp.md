## Engine-specific additions not ported

Native skeletal scale output remains unsupported in current targets. In authored
SMD input the new reference accepts three trailing scale components and emits
extended animation flags (`0x88` in the changing-scale fixture); one trailing
component is rejected. DMX Vector3 bone scale emits extended flags (`0x60` in a
static-scale fixture). REA confirms the importer records Vector3 `scale - 1`;
this is not QC `$scale` or animation position scaling. The official changelog
explicitly requires an engine branch supporting scale. Current MDL readers and
writers do not claim that extension. DMX non-unit bind and sampled bone scale now
fail before output publication rather than silently disappearing. Identity scale
and unrelated material attributes are covered separately. A model-1 DMX fixture
using integer-tick startTime/durationTime/offsetTime and integer fps produces five
frames in all three compilers: old reference and v1.3.0 omit scaling (`0x20`),
while the new reference emits changing scale (`0x88`). A different typed-time
fixture yields only one reference frame and is not used to infer dynamic parity.

`$retarget` is MVZ-only in official documentation. The new reference accepts a
model path and options in a brace block and writes additional header/table data;
old reference rejects it. Isolated empty/rootscale probes establish compilation
and serialization, not runtime behavior or full retarget semantics. The project
now gives a specific unsupported-target error and preserves existing outputs.
This does not affect `subtools/l4d_animswap` offline retargeting.
