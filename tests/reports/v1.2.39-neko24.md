# v1.2.39 NekoMDL 2.4 compatibility validation

Validated locally on Windows x64 on 2026-10-24. This records the implementation
on top of `c8a52574d8cc41b7bc70e8016a1d700029b5cb6f` (v1.2.38), not a published
release certification. The four additions follow the supplied executable's measured behavior;
they do not establish complete NekoMDL 2.4 parity.

The [reference investigation](2026-10-24-nekomdl-2.4-reference.md) retains the
separate binary identities and comparison results. That executable reports
2.4.0 at runtime but 2.3.0 in Windows version resources. A complete official
2.4.0 changelog, release date and stability designation remain unconfirmed.

## Implemented behavior

| Feature | Selection and result |
| --- | --- |
| Source reuse bypass | `$DisableCache` is case-insensitive, takes no arguments, and disables subsequent loaded-source cache lookup and insertion. Previously loaded sources stay owned and unchanged. It works in either QC mode; parsed DMX and scene caches remain separate. |
| Multiple material groups | Final `$qccompatibility neko` with more than one `$texturegroup` appends `neko_material_group` keyvalues and one trailing identity skin row. `i` is the first alternative row and `c` its count; alternatives stay in declaration order, without a Cartesian product. Single-group and native output retain their existing behavior. |
| BodyGroup state limit | Final `$qccompatibility neko` rejects the product of choices at or above 2^31 using checked arithmetic. Native mode retains its existing base/preset checks and accepts 31 binary groups with representable bases. |
| Windows reload request | After successful file output, `-reloadhlmv` sends the L4N extension request to a `Valve001` window with a one-second timeout, then attempts the existing HLMV notification. Failed compilation, `-verify`, and omission of the option do not notify. |

Example QC placement:

```text
$qccompatibility neko
// Existing model, body, sequence and material definitions follow.
// Place this before a source that must be loaded again with current settings:
$DisableCache
```

The last `$qccompatibility` directive selects final material-group and BodyGroup
output policy; a later `native` restores native output policy. Conditional
expressions still use the mode active when parsed. `$DisableCache` stays enabled
for the remainder of the QC and may increase loading work and memory usage.

Group metadata preserves authored model keyvalues and accounts for their size
limit. The extra identity row participates in the skin-table budget. Empty or
default-only groups have zero alternatives. Ambiguous group names (empty,
case-insensitive duplicates, quotes, backslashes or control characters) and an
authored root `neko_material_group` key are rejected. Nested keys and scalar
values with that text remain valid. These ambiguity checks are implementation
safeguards, not claims about unmeasured reference rejection behavior.

The game payload is `l4n_reload_model models\<model path>.mdl` followed by LF and
NUL. `WM_COPYDATA.dwData` and the sender parameter are zero; `cbData` includes
the NUL. Model paths with control bytes below 0x20, quotes or semicolons skip
the game request. Delivery failure is reported after successful model output.

The new compiler regressions decode emitted MDL/VVD data and animation poses.
They cover cache reuse versus fresh animation imports at scales 1/2/3, retention
of earlier clips, private body scaling, rejection of cache arguments, named
material ranges and identity rows, final mode selection, existing keyvalues,
invalid names and conflicts, explicit `$set` alternatives, absent materials,
skin capacity, and the 30/31 binary BodyGroup boundary. Failure probes verify
that prior outputs remain unchanged.

NewPage's body imports were already private before this change: unlike the
reference's repeated-body example, its bodies already honor successive scale
settings without `$DisableCache`. The cache regression therefore uses reusable
`$animation` sources to exercise the new switch, with a separate VVD check to
preserve the existing body behavior.

The Windows suite creates its own game and HLMV receivers on a hidden private
desktop. It verifies the actual child desktop before launching the compiler,
the exact payload and zero fields, exact-title HLMV selection against a decoy,
the no-notification cases, and a receiver that stops pumping messages. The
compiler must finish within a bounded test timeout. No real application receiver
was used.

Windows package verification also runs this suite against the extracted
release compiler with `--require-all`, which treats any skipped protocol test
as a failed package check. The existing compatibility package check runs all
456 tests on both Windows and Linux.

## Remaining limits

Actual L4N game reload and consumption of `neko_material_group` metadata remain
unverified. Successful message delivery does not establish game support, and
ordinary L4D2 hot reload is not claimed. The local checks recorded above do not
include Linux builds or real-model/game acceptance. Subsequent cross-platform
build and publication results are recorded in the
[v1.2.39 release](https://github.com/NPCodex/newpage-merge-mdl/releases/tag/v1.2.39)
and its linked Actions run. Reference executables and user model assets are
not added to source or packages.
