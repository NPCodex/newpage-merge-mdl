# v1.2.38 同配置性能基线

2026-10-22，同一 Windows 主机、相同构建设置的三个自制样本，**普通 CLI 的
进程耗时均通过 +20% 门槛**，变化范围为 -1.8%～+1.8%。两版、两种运行模式的
模型文件逐字节相同，每组七轮输出也完全一致。这不是所有模型或最终发行包的提速声明。

可选 `-perfjson` 的持久报告发布有额外成本：内部编译计时和峰值内存通过门槛，
但 small 与 clips-morphs 的完整进程耗时分别增加 24.1%、28.6%，**报告模式的
完整耗时门槛未通过**。本轮没有隐藏这个结果，也没有降低持久恢复或别名保护要求。

## 构建与测量身份

从 Git 导出两份独立源码，在独立目录完整构建 compiler 及其依赖；未使用官方二进制
与开发二进制混比，未使用 SDK、游戏或用户模型。两边实际生成的编译/链接设置已核对：

- MSVC `19.51.36260.0`，Visual Studio 18 2026，CMake `4.3.1`，Windows x64。
- `MinSizeRel`，`/O1 /Ob1 /DNDEBUG`，静态 CRT `/MT`，IPO 关闭。
- `NEWPAGE_COMPACT_RELEASE=ON`；可重现路径处理和分离符号均关闭，使旧版和新版采用相同设置。
- 仅源码版本宏、源码路径和本轮实现不同。普通 CLI 与报告模式使用同一对程序。

精确构建参数、编译器文件 SHA、源码归档 SHA、候选覆盖文件 SHA、输入依赖 SHA、
每轮数值、输出 SHA 与阶段中位值见 [机器可读证据](v1.2.38-performance.json)。
此候选身份不冒充随后其他源码修改的构建。最终开启 IPO 的发行配置仍需建立自己的基线。

每个样本、每个版本、每种模式均为 **1 次首次进程 + 1 次预热 + 5 次测量**。
首次进程单列并排除在中位数之外；没有清空操作系统磁盘缓存，不能称为冷盘测试。
测量窗口内未运行游戏或其他本机构建。外部计时使用高精度 `time.perf_counter()`。

此模式不凭空填写未采集的内部阶段或峰值内存。

## 可选性能报告

`-perfjson` 的内部 `total_ms` 截止于模型写入后的 `tWrite`：候选包含报告锁/初始日志
准备，却不包含随后的报告持久提交。完整进程 wall 才包含报告提交；二者不能互相替代。
原生 JSON 两侧均为 schema 1，新增场景缓存字段没有被当作旧版已有指标进行比较。

| 样本 | 基线 / 候选进程中位 ms | 进程变化 | 基线 / 候选内部总计 ms | 基线 / 候选峰值 MiB |
| --- | ---: | ---: | ---: | ---: |
| small | 76.50 / 94.91 | +24.06%，未通过 | 66.69 / 71.70 | 8.78 / 8.86 |
| large-grid | 140.27 / 163.60 | +16.63%，通过 | 130.31 / 138.45 | 31.85 / 31.90 |
| clips-morphs | 93.13 / 119.73 | +28.57%，未通过 | 83.41 / 93.13 | 10.97 / 11.11 |

| 样本 | 基线加载 / 编译 / 写入中位 ms | 候选加载 / 编译 / 写入中位 ms |
| --- | --- | --- |
| small | 1.66 / 0.24 / 64.80 | 0.99 / 0.21 / 70.51 |

Linux peak RSS 混作同一种内存指标。该样本集不能证明普遍的网格或动画算法提速。

## 已做优化与保留成本

报告工作副本原先先刷盘一次，事务提交又把它复制至真正发布暂存文件并刷盘。
现在工作副本仍严格检查写入和关闭，最终发布暂存文件仍由事务刷盘；仅去掉恢复流程
从不依赖的工作副本的重复刷盘。目标路径的规范化身份也只计算一次。
锁、输入/模型别名检查、intent/ready/commit 持久日志、冲突检测和恢复协议保持不变。

修正后通过 8 项实际编译器报告保护测试、17 项持久输出测试，其中新增报告在
begin、journal、prepared、ready、backed_up、published、committed 七个检查点
强杀后重启及重复恢复验证。另有 10 项基准工具测试检查构建/输入/schema/模式错配、
阶段外耗时回归和门槛边界。

目前额外成本主要属于可选报告自身的单独持久事务。进一步降低它需要设计并验证
专用单文件提交协议或与模型发布合并的事务，不能直接删除日志、刷盘或恢复检查来
满足比例门槛。普通 CLI 对照没有该回归；报告模式的超限作为明确限制保留。

## 复现与门槛

`tests/benchmark_models.py` 现在拒绝构建配置、编译器身份、完整自制输入目录、
采样协议、报告 schema 或运行模式不同的基线。默认同时检查完整进程耗时及可用的
内部总耗时 +20%、峰值内存 +15%。基准输入目录须自包含，且不得存放生成输出。

```text
cmake -S SOURCE -B BUILD -G "Visual Studio 18 2026" -A x64 -DCMAKE_INTERPROCEDURAL_OPTIMIZATION=OFF -DCMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded -DNEWPAGE_REPRODUCIBLE=OFF -DNEWPAGE_SEPARATE_SYMBOLS=OFF -DNEWPAGE_COMPACT_RELEASE=ON
cmake --build BUILD --config MinSizeRel --target mdlcompiler --parallel 3
python tests/performance_fixtures.py FIXTURES
python tests/benchmark_models.py COMPILER --qc FIXTURES/small/small.qc --qc FIXTURES/large-grid/large-grid.qc --qc FIXTURES/clips-morphs/clips-morphs.qc --runs 5 --warmup 1 --build-cache BUILD/CMakeCache.txt --configuration MinSizeRel --source-revision REVISION --report baseline.json --plain
```

用候选程序和对应 BUILD 重复最后一条，并添加 `--baseline baseline.json`，输出改为
candidate.json。报告模式需从两侧命令都去掉 `--plain`，使用另一对 JSON；禁止混比。

原始原生阶段全量数据、日志、命令与两份隔离源码留在
`D:/newpage-performance-20261022`。早期官方 v1.2.37 与 Release/动态 CRT 开发版的
不同配置观测仍留在工作区 `.diagnostics/toolkit-audit-post-v1237`，没有用来判定本轮门槛。
场景缓存专用结果见 [缓存报告](v1.2.38-scene-cache.md)，不从这三组 SMD/VTA 样本推断缓存收益。
