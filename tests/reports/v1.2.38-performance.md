# v1.2.38 开发性能观测

2026-10-21，在同一 Windows 主机使用 `tests/performance_fixtures.py` 生成的三组
自制输入，运行当前 MSVC Release、动态 CRT、IPO 关闭的开发程序。
这不是最终安装包性能声明，也不代表所有模型可获得相同比例的改进。

程序 SHA256：`4ebda19076e4180c12c0d02d98ad13ceb8c51106dd317cfe5be22123241d720e`。
每样本先运行一次，再测量五次；所有六轮模型产物 SHA256 一致。
首次进程测量没有清空操作系统磁盘缓存，不能称为真正冷盘测试。

| 自制样本 | 首次进程 ms | 测量中位 ms | 峰值 working set 中位 MiB | 加载 / 编译 / 写入阶段中位 ms |
| --- | ---: | ---: | ---: | --- |
| small | 157.1 | 79.5 | 9.4 | 1.14 / 0.26 / 77.76 |
| large-grid，100×100 网格 | 155.3 | 152.8 | 32.2 | 51.89 / 3.59 / 97.29 |
| clips-morphs，24 clips / 16 morphs | 225.2 | 106.6 | 11.6 | 16.26 / 3.72 / 86.75 |

每阶段分别取中位数，因此其和不必等于总体中位数。写入阶段包含既有输出发布事务，
这些短任务中的占比较高；不能直接归因于网格或动画算法。Windows working set 与
Linux peak RSS 不是同一种测量，不混合比较。

同机还保存 v1.2.37 官方程序的三次测量及一次预热，程序 SHA256
`313cf87f53e27175cbfc8c0ad008bc06f93e8a4f03349be18d7ee929d45790ac`。
旧官方程序的优化、链接和 CRT 配置与当前开发程序不同，因此没有用这两组结果
宣称算法提速、算法回归或通过回归门槛。

测量工具可用 `--baseline` 对比同机、同输入的历史 JSON，默认门槛为总耗时 +20%、
峰值内存 +15%。调用者还必须核对工具链、构建配置、系统负载和输入依赖一致；
工具的机器标识/顶层 QC 校验不能替代这些条件。最终发行配置需要建立自身基线。

```text
python tests/performance_fixtures.py isolated-fixtures
python tests/benchmark_models.py path/to/NewPageMergeMDL --qc isolated-fixtures/small/small.qc --qc isolated-fixtures/large-grid/large-grid.qc --qc isolated-fixtures/clips-morphs/clips-morphs.qc --runs 5 --warmup 1 --report performance.json
```

原始全部采样、阶段值、机器身份、QC 与输出散列保存在本机
`.diagnostics/toolkit-audit-post-v1237/performance-candidate-1238.json`；历史文件为
同目录 `performance-baseline-1237.json`。样本不含游戏或用户资产。

场景缓存启用/禁用的结果等价和预算淘汰已由
[独立回归](v1.2.38-import-validation.md) 验证；这些固定样本不是专门构造的重复
场景访问基准，不能据此断言缓存命中收益。减帧的保留帧数/参考误差也与编译总耗时
分别记录，避免把更少帧数当作已证明的整体提速。
