## In-game blend probe

The local `c1m1_hotel` server ran Left 4 Dead 2 **2.2.4.3**, executable build
**10097**, dated **2026-06-30**. The existing installed runtime, including the
user's Necola/Uplift/Bridge modules, was preserved; this is not a clean-install
or Linux gameplay result.

The unique test addon loaded the compiled Rochelle mesh as four
`prop_dynamic_override` actors. Their actual `m_nSequence` values were queried
from the engine and matched the independently inspected compiled sequence table:

| Actor | Sequence | Engine sequence index | Recorded samples |
| --- | --- | --- | --- |
| 0 | `Walk_Pistol` | 9 | 48 |
| 1 | `Run_Pistol` | 12 | 48 |
| 2 | `Idle_Standing_Rifle` | 3 | 48 |
| 3 | `Idle_Crouching_Pistol` | 6 | 48 |

The final probe completed **240 updates**, scheduled every 0.1 seconds, with
**0 failures**. At each update it applied `move_x`, `move_y`, `body_yaw` and
`body_pitch` through the native integer-index pose API and checked the returned
values against the requested values within 0.001. It recorded 192 actor samples
at ticks 0, 5, ..., 235. All sampled left/right foot, muzzle and eye attachment
coordinates were finite. Sampled parameter ranges covered both signs and the
center: movement x −0.989423 to 0.990607, movement y −0.999965 to 1, yaw
−89.986° to 89.8053°, and pitch −89.9416° to 45°.

All four probes rendered with the expected standing/crouching/locomotion poses;
the observed sweep and separate yaw ±75° / pitch ±30° views showed aim changes
without visible missing-model/error materials or gross mesh collapse. Foot
attachments varied during walk/run and upper-body attachments varied during
aiming. Fixed actor origins intentionally isolate the pose evaluation: these
measurements do not establish a continuous error bound, foot contact quality,
root-motion behavior or transitions between survivor activities.

The accepted run is the **last** spawn-to-DONE block in the captured log. Earlier
probe setup used the wrong VScript argument type and is excluded. The initial
UI-only launch attempt was also not accepted; it has a separate attempt record.
The accepted session used the engine's native local net-console interface and
ended with normal `quit` / `Server shutting down`. After exit, the harness
verified restoration of configuration/log bytes, removal of only the diagnostic
addon, and unchanged protected executable/module/VPK hashes.

## Scope

The actual production sequences exercise aim grids, additive/local layers and
bone masks. They do not supply a pose-driven layer envelope; that case remains
covered by the separately authored 2×2-grid regression. Unsupported touch-IK
targets still produce the documented commented diagnostics. This character
probe imports the whole render mesh; it does not certify facial flexes, eyeballs,
all survivor activities, weapons/reload, touch-IK, ragdoll physics or complete
gameplay compatibility. Recording muzzle coordinates does not certify an
attached weapon. The authored pose-envelope regression is offline evidence;
the selected real sequences do not add in-game pose-envelope coverage.
