The following history records the defects that this check found and fixed.

The ordinary Windows run completed 240 authored mutations: 69 accepted, 171
rejected, no crashes, timeouts or RSS/log-budget overruns. It did not enable
sanitizers and cannot substitute for the Linux check.

The first actual Clang ASan+UBSan run found a signed-left-shift bug while compiling
the valid seed model in `writemdl.cpp:3164`, before any mutations ran. Commit
`641b7e3` uses defined unsigned wrapping arithmetic while preserving bit-27
feedback and every iteration's checksum header writeback.

[Run 39752234113](https://github.com/NPCodex/newpage-merge-mdl/actions/runs/39752234113)
passed the checksum operation and exposed misaligned `int32` access in packed VTX
records at `writevtx.cpp:1445`, still while compiling the valid seed. Commit
`d3930b8` reads the eight shared strip/strip-group fields with `memcpy`, keeping
the exact byte layout and values.

[Run 39755155127](https://github.com/NPCodex/newpage-merge-mdl/actions/runs/39755155127)
then reached a separate misaligned `SGCommon` structure access at
`writemdl.cpp:2531`. Commit `7216078` copies both readers' shared fields into
aligned local structures without changing the packed format or output values.

[Run 39756067020](https://github.com/NPCodex/newpage-merge-mdl/actions/runs/39756067020)
passed seed model compilation/decompilation and seven valid input controls, then
found a misaligned IK-chain read in the valid VMD control. Commit `75c13ac`
copies chain/link records to aligned locals while retaining original relative
offset bases. A focused review also found byte-packed SubD topology accessed
through `uint16_t*`; the same commit replaces it with `memcpy` reads/writes and
adds two existing valid SubD models to the sanitizer workflow.

[Run 39756572960](https://github.com/NPCodex/newpage-merge-mdl/actions/runs/39756572960)
passed both SubD models. Clang retained an alignment assumption on the typed
IK-link `memcpy` source, so `b91282c` additionally range-checks it as raw bytes.
Windows MSVC Release also passed both SubD models, 19 VMD motion cases and 18
VMD invalid-input/output-preservation cases at `75c13ac`.

[Run 39756932797](https://github.com/NPCodex/newpage-merge-mdl/actions/runs/39756932797)
passed all eight valid controls and both SubD tests, then completed all 240
samples within the 180-second mutation/reduction budget: 67 accepted, 168
rejected and five sanitizer failures grouped into four retained findings; no
crashes, timeouts or RSS/log overruns. The retained minimized samples exposed a
truncated SMD without a skeleton reaching a null bind pose, and two types of
MDL sequence integer overflow. Commit `5fc10b0` rejects missing SMD skeletons

before QC export while retaining valid external declarations. The MSVC build
passed all 16 decompiler integrity tests and rejected all three minimized MDL
reproducers with exit code 1. The integrated sanitizer rerun above passed.
This is a bounded experiment, not proof that arbitrary model files are safe.
