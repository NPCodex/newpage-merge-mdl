## Confirmed differences

### Source reuse switch

Seven isolated triangle compiles establish that `$DisableCache` is a new,
case-insensitive, no-argument QC directive. The old executable rejects it;
the new executable accepts both ordinary and mixed case. Adding `0` or `1`
leaves that token to be rejected as a command; it is not a boolean option.

Static inspection resolves the command-table handler at `0x14007863c` to a
write of 1 at `0x14b6451b0`. `Load_Source` at `0x14008600c` tests this flag
before looking up an existing loaded source. The handler is an eight-byte
leaf; Ghidra decoded its instruction but did not create a function for it.

Three further compiles use the same SMD twice with `$scale 1` before the
first body and `$scale 2` before the second. Old and new default behavior
reuse one loaded source and emit both bodies at scale 1. Adding
`$DisableCache` between bodies makes the new executable read the source
again and emit the second body at scale 2. MDL body vertex ranges and VVD
positions were inspected; the subsequent sequence also reloads the file.
This establishes subsequent source-reuse bypass, not disabling every
internal importer cache or a performance improvement.

### Multiple named texture groups

Four compiles compare one and two standard `$texturegroup` blocks, each
with a default row and one alternative. One group yields the same two
skin families in both references, without extra keyvalues.

With two groups, the old reference emits two default rows in this fixture.
The new reference emits four rows plus the following generated metadata:

```text
mdlkeyvalue
{

neko_material_group { "group_alpha" { i 1 c 1 } "group_beta" { i 2 c 1 }}
}
```

For materials `[probe_material, probe_second, probe_red, probe_blue]`, new skin rows are
`[0,1,2,3]`, `[2,1,2,3]`, `[0,3,2,3]`, `[0,1,2,3]`.
The last row repeats the default: this is **not a Cartesian product** of
the groups. Static inspection at `0x14009119c` corroborates per-group
alternative indices/counts and the final identity row. The token
`neko_material_group` is generated keyvalue text, not an established new
QC directive. A consuming game's support for these keyvalues was not tested.

### BodyGroup state limit

Four compiles use one rendered two-triangle body plus 30 or 31 groups containing
two blank choices each. Both references compile 30 groups (2^30 states).
The old reference also compiles 31 groups; the new one fails with
`Too much $BodyGroup state.` and produces no model output.

The new helper at `0x140092440` multiplies the current group's base and
choice count in 64 bits and requires the result to be below 2^31.
This is a stricter reference policy, not evidence that NewPage's existing
base/preset validation is missing: NewPage deliberately accepts 31 binary
groups with representable bases, checks actual preset values and rejects
later selectable groups with an unrepresentable base. Existing tests
`test_bodygroup_combination_capacity_is_checked` and
`test_final_bodygroup_product_does_not_reject_valid_bases` document that
choice. They were inspected, not rerun as part of this reference-only pass.

### Expanded reload notification (static evidence only)

New imports are `USER32!FindWindowA` and `USER32!SendMessageA`. The existing
`-reloadhlmv` flag still guards a post-success reload helper, now at
`0x1400a648c`. Before its HLMV notification it searches for a `Valve001`
window and sends `WM_COPYDATA` (`0x4a`) carrying
`l4n_reload_model models\\<model path>` followed by a terminator.
The old HLMV `mx_class` / `WM_COMMAND 1017` path remains.

This establishes a notification attempt in static control flow. No real
game received the message in this investigation. Which extension accepts
the command, whether it reloads successfully, and its game compatibility
remain unverified. It must not be advertised as standard L4D2 hot reload.

## Relationship to the maintained compiler

| Finding | Current source status | Interpretation |
| --- | --- | --- |
| `$DisableCache` | Not implemented. `$SceneCacheMiB 0` disables parsed scene retention, not QC `sourceCache` reuse or `dmxCache`. | A concrete future compatibility addition; the existing setting is not equivalent. |
| Named material-group metadata | Multiple groups already flatten alternative skin rows; group names/boundaries are discarded. No automatic `neko_material_group`. | Metadata compatibility remains open; do not claim ordinary engine support. |
| Final BodyGroup product rejection | Checked bases and preset arithmetic already exist, with a deliberately more permissive final-product policy. | Preserve the documented intentional difference unless a separate compatibility policy is introduced. |
| L4N reload message | Current `-reloadhlmv` only notifies HLMV. | Reference protocol discovered; real receiver behavior remains unknown. |

No compiler implementation, version, release, upstream baseline or supplied
reference binary was changed. Both READMEs were reviewed: their concise
feature/compatibility links remain accurate; detailed new reference status
belongs in COMPATIBILITY.md and FEATURE_MATRIX.md.
