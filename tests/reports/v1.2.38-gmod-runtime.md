# v1.2.38 VRM runtime: actual GMod observation

Tested 2026-10-21 in Garry's Mod 64-bit, engine `2026.10.19`, on `gm_flatgrass`.
The isolated addon used previously authored minimal meshes and the current
`integration/gmod/newpage_vrm.lua`; no user model or workshop addon was needed.

The current fixed-step code ran through the real `BuildBonePositions` callback.
Four six-second observation phases each produced more than 1,400 nonzero-time
callbacks, finite spring tails and no runtime error. Observed callback rates
were 235.8–237.0 per second. Requests to change `fps_max` from Lua did not change
the observed rate in this installation; these phases **do not establish four
different real frame rates**. The separate Lua 5.1 tests cover 30/60/120/240 FPS
and pause recovery numerically. This run establishes current-module integration
and rendering at the actual high callback rate.

All six client and two server checks passed: model/material loading, mesh-state
bodygroups, VRM expression/flex/material/UV sampling, both LODs and procedural
bone matrices, spring attachment and finite tails, two collision bodies with
total mass 10, and finite physical rest above the ground. The screenshot shows
the intentionally minimal triangle test models, not a production avatar.

All backed-up game configuration hashes were restored. The isolated addon and
test data were removed from the game and archived with evidence under
`.diagnostics/gmod-v1238` in the local workspace. No original model was modified.

This does not certify arbitrary rigs, visual hair quality or a fixed maximum
error for continuous animation. Raw client/server JSON, module hashes, screenshot
and cleanup verification remain in that local evidence directory.
