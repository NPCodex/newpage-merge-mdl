# v1.3.2 — supplied StudioMDL++ screenshot follow-up

The [2026-10-30 audit](2026-10-30-studiomdlpp-screenshot-audit.md) found three
concrete diagnostic gaps in v1.3.1. This change implements those gaps without
adding engine-specific scale or retarget serialization.

## Implemented behavior

- **File spelling:** on Windows, accepted loose-file paths are checked against
  the opened file's normalized disk spelling. A case-only difference warns with
  the requested path, disk path and Linux portability hint. Checks cover QC,
  includes, resolved source files and loose mounted resources, including directory
  components. Each normalized requested spelling is checked once per compile;
  lookup order and output paths remain unchanged. Drive-letter case is ignored.
  Symlink/junction target changes that are more than case-only are not diagnosed;
  VPK entry spelling is outside this warning. Failed opens retain their normal
  errors. No case-insensitive fallback was added to Linux or case-sensitive roots.
- **Degenerate IK:** after final bone resolution, warn once per chain if either
  parent-to-child bind segment is at most `1e-6` model units. The warning identifies
  the chain, three bones and both lengths. Ordinary straight limbs, bent limbs
  and short nonzero limbs above that threshold remain valid without this warning.
  The chain and serialized data are retained; missing ancestors still fail.
  This is a bounded geometric check, not a full animation-time IK solver audit.
- **Weightlist diagnostics:** QC animation weightlist commands retain their
  authored token location, source excerpt/caret and macro/include provenance until
  compile-time name resolution. Unknown masks now report `file(line,column)`,
  including macro bodies, command-list definitions and appended commands. Names
  may still be declared after their use. Columns are 1-based UTF-8 source byte
  offsets; tabs in the caret prefix retain their original tab characters.
  Non-QC inputs without token provenance keep the ordinary error text. Other late
  semantic errors do not automatically gain this provenance.

## Local validation

The MSVC Windows Release compiler was built as v1.3.2. Compiler identity, source
hashes, log hashes and measured results are in the accompanying
[JSON](v1.3.2-studiomdlpp.json). The focused 35-test subset is already included in
the full 502 compatibility tests; it is not an additional 35 distinct cases.

- **502 compatibility tests** passed, including eight new authored regressions.
- **10 direct-output**, **6 compiler-integrity** and **10 performance/report-output**
  tests passed.
- **10 CONTENT/VPK mount tests** passed using a freshly compiled MinGW resource
  lookup helper built from the modified resource source. The main compiler and
  helper have distinct identities and roles.
- Medusa expressions/no_expressions both compiled for the actual GMod target.
  Each retains 81 bones and 46,510 vertices; all five model companion files per
  variant are byte-identical to the retained v1.3.1 control. All 236 original
  Medusa files and target `gameinfo.txt` hashes remain unchanged.
- The maintained compatibility overlay was regenerated and checked against
  PulseModel `0396e3d`; source diff whitespace checks passed.

Detailed local logs and scripts are retained under
`D:/newpage-merge-mdl/local-build/studiomdlpp-screenshot-audit/`.
The standalone compiler snapshot is in its `v1.3.2/` directory with
`SHA256SUMS.txt`. It is a compiler snapshot, not a complete installation ZIP.

No Linux compiler build, full distribution rebuild, new game run or Release
publication is established by this local validation. Previous game/platform
evidence retains its original version and scope. Native skeletal scale and MVZ
`$retarget` remain unsupported; documented CE output/procedural defaults remain
intentional differences. The unspecified texturegroup/SMD crash fixes in the
screenshot still cannot be equated to a particular historical fault without a
reproducer.
