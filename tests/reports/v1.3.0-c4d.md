# v1.3.0 C4D rig import evidence

Validated 2026-10-25 with an isolated Windows x64 Release helper built using
Cineware 22.008 and MSVC 14.44.35207. No Cinema 4D application is installed at
the previous 2026/2027 locations. The real application fixture and independently
evaluated reference JSON were authored in licensed Cinema 4D 2027 on 2026-10-22;
this validation compares against those preserved results.

Helper SHA256:
`158e0b5993e9fb4c3371d4b9d2a0919a1913d495afa1b66d5aa4d7052efdce19`.
The main compiler used for these local integration checks is the v1.3.0 local
Release candidate copied from the shared development build, SHA256
`2a6d31ab139415d0c28f6af18324e317ae340b9b45a5aa984269656b1cc4daf8`.
These identities do not claim the final v1.3.0 packaged compiler was checked;
the release workflow must repeat this suite against that package.

All **17 C4D regression groups pass**, including the original static and saved
generator/deformer tests. The helper imports the documented bounded single-mesh
linear skin and linear TRS timeline. The independent evaluator reads joint links,
inverse bind matrices, point weights and animation samplers from exported GLB;
it does not insert the expected weights from the author's script.

The maximum joint world-matrix component error is `2.23517418e-8`. All six
original bind points, UVs and both linked joints survive. The compiled MDL/VVD
contains both named joints, six vertices, the two expected 50/50 blended vertices
and one 31-frame, 30 fps skeletal clip.

An independently authored SDK fixture adds nonidentity mesh and joint binds,
two materials, a shared-position UV seam and translation/HPB rotation/nonuniform
scale tracks. At frames 0/15/30, eight exported split vertices agree with an
analytical skin calculation to five decimal places in meters. Normal Source
skeletal import rejects animated scale; explicitly requesting
`BakeSceneAnimation C4D_Timeline SceneSampleRate 30` succeeds and records 31
timestamped vertex-animation frames.

Eight SDK-authored invalid rigs cover unnormalized weights, dual-quaternion
blending, spline keys, constraint tags, duplicate object names, muted tracks and
singular bind matrices and a reserved synthetic-root name. Each fails without converted output and preserves the
previous compiled model. Existing missing-cache, corrupt topology/UV, bare
weight-tag and nonlinear animated-object rejection cases also pass.

The implementation reads original weighted polygon points even when Cinema 4D
marks them as controls for a saved deformation cache. It applies the geometry
bind matrix to joint inverses and remaps point weights before material splitting.
The Cineware 22 sparse indexed weight accessor repeats an entry for the actual
2027 file; the point-addressed accessor works. Quantized sums are normalized only
after passing a `1e-4` sum tolerance, never used to repair incomplete weights.

This establishes the [documented subset](../../tools/c4d_bridge/README.md), not
general Cinema 4D compatibility. Constraints, takes/layers, nonlinear curves,
multi-mesh skins, nondefault Skin modes, dynamic skinned-mesh transforms, complex
deformers/plugins and simulation remain unsupported and explicitly rejected.
No new live application run, arbitrary rig, game rendering or shader-baking
claim follows from these results.

Local reproducibility:

```text
python tests/c4d_bridge_test.py <isolated-compiler-directory>/NewPageMergeMDL.exe -v
```

The candidate helper must sit beside that compiler. Self-authored fixture sources
are `tools/c4d_bridge/fixture.cpp` and `author_fixtures.py`; proprietary SDK headers,
libraries and application files are excluded from the repository and archives.
